# FPL Planner design

Approved direction: the conversation authorises a dedicated public joellimrl/fpl-planner repository, implementation and free standard GitHub Actions scheduling. No Streetbot, AWS or paid API. Private current squad state must not be published.

## Purpose
Produce reproducible numerical player forecasts and legal multiweek transfer plans, subtracting hits and comparing any immediate changes with waiting. Report statistical assumptions and optimisation limits; do not claim guaranteed future points or an unbounded global optimum.

## Approach
Public GitHub repository and standard ubuntu-latest Actions, Python 3.12, scipy/HiGHS mixed-integer optimisation, cryptography for private reports. Compared alternatives: AWS rejected for hard-zero budget; local scheduler needs the PC on. Implement directly in a new isolated repository, without touching Streetbot. Author implements inline; one fresh code reviewer before publishing.

## Inputs and data boundaries
Public sources: FPL bootstrap-static, fixtures and element-summary. Cache compact complete-gameweek histories under data/ and version frozen public forecasts. No passwords, browser cookies or API keys for FPL.
Private FPL_TEAM_STATE secret: effective_gameweek, squad entries with element, purchase_price and selling_price (integer tenths), bank, free_transfers and chip availability. Seed from today's verified saved team. Never commit this input, its team ID or personalised plaintext output. Public reports contain league-wide rankings and model diagnostics only. Personal reports are AES-GCM encrypted before entering reports/private; a generated REPORT_ENCRYPTION_KEY lives in Actions Secrets and ignored local .private/report.key. Provide local decryption/download tooling; no paid notification provider required.
Missing or stale private state must not silently produce apparently current recommendations. The public pipeline must still work without secrets. Personal planning requires state effective_gameweek equal to the next event. Later state changes can be uploaded with a local CLI. This initial version deliberately requires refreshed state each new gameweek; no unreliable cloud login.

## Forecast model v1
Only finished AND data_checked gameweeks contribute. Include zero-minute rows for playing-time estimation, not as 90-minute performances. Exponentially weight by gameweek age (decay 0.85); shrink xG/xA rates with 450 pseudo-minutes towards position priors. Estimate appearances, 60+ minutes, expected minutes and threshold probabilities from weighted records with conservative smoothing. Score using current positional rules: GK goal 10, DEF 6, MID 5, FWD 4, assists 3, appearances 1/2, clean sheets 4/4/1/0, defensive contributions threshold 10 DEF and 12 MID/FWD, two points; include bonus, cards, saves and goal-concession deductions. Disclose approximate components, assist calibration and availability assumptions. Venue/opponent adjustment uses team goals and goals conceded from completed fixtures with smoothing and bounded ratios, not invented FDR probabilities. Sum matches in doubles; blanks score zero. Availability factors apply conservatively through horizon. No fitted predictive-quality claims without backtests.

## Optimiser v1
Full eligible player pool and six gameweeks (configurable up to six). MILP jointly selects squad, starting XI, captain, buys/sells, bank, free-transfer usage and hits each week. Exactly 2 GK/5 DEF/5 MID/3 FWD, max 3 per club, starting GK1 DEF3-5 MID2-5 FWD1-3. Spending uses actual initial sale prices, with original-ownership bookkeeping so selling and rebuying cannot re-use original discounts. Future prices held constant, no chips in v1. Up to two transfers per week as an explicit search constraint; include zero transfers. Free transfers roll to max five; extra transfers cost four points. Solve twice: unrestricted first action and forced hold now, both allowing future actions. Exact same deterministic objective and configuration; record solver status, dual bound and gap. Fixed node budget plus an operational timeout; never call a time-limited incumbent proven optimal. Objective counts starters plus extra captain points; auto-sub and vice-captain fallback are not modelled in MILP v1, and no bench points are incorrectly added. Rank bench and vice by forecast. Display these limitations prominently.

## Automation and reliability
Hourly schedule at minute 23 UTC, workflow_dispatch manual check/force collection. Fetch bootstrap cheaply first and skip full work if the newest completed gameweek has already been reported. On initial setup process latest only, not all historic weeks. Workflow concurrency serialises report updates; commits only after all required public collection succeeds. Retries bounded and no silent partial datasets. Encrypt before writing personal output. Persist public manifest after successful results. Re-runs reuse existing report when snapshot and state fingerprints match. Public logs and job summaries contain no personal recommendation data. Restrict secret-bearing work to owner repo schedule/dispatch, no PR secret exposure. GITHUB_TOKEN contents:write only where needed. No artifacts, cache actions, Pages, packages, paid runners or third-party paid endpoints. Checks on push/PR are read-only and receive no secrets. Scheduled requests can be delayed; off-season 60-day inactivity can disable scheduling and README explains re-enabling without artificial keepalive commits.

## Acceptance
Offline tests cover mathematical rates, blank/double events, invalid/missing/old state, playing-time thresholds, no future leakage, starting formation, exact money constraints, original sale-price reuse, free transfer cap/hits, hold baseline, no secret/plaintext persistence, duplicate-run gating and failure atomicity. Live public API smoke test; verify a real standard-runner workflow succeeds and skips correctly on repeat. Inspect Git staged content before any public push. Use generic fixture test data. Preserve local decrypted report and key only in ignored .private. Publish only after reviewer checks and meaningful tests. No FPL transfers by automation; recommendations only.
